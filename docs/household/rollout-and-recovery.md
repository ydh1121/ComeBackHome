# 생활비·자료 답변 기능을 운영에 반영하는 순서

이 문서는 실행 준비서입니다. 문서를 읽거나 PR을 만든 것만으로 운영 DB 변경이나 배포가 실행되지는 않습니다. 담당 실행자가 승인된 커밋으로 아래 순서를 수행합니다. 사용자에게 SQL 복사·붙여넣기를 요구하지 않습니다.

## 적용 순서

1. PR의 필수 전체 회귀와 비공개 모듈 검사가 모두 성공한 **같은 커밋**을 고릅니다. 40자리 커밋 SHA를 기록합니다.
2. 기존 GitHub `Apply ComeBackHome D1 Migrations` 워크플로에서 검수된 브랜치를 선택합니다. 새 프로젝트나 워크플로를 만들지 않습니다.
3. `batch`는 `household-0013-0015`, `confirmation`은 `APPLY_REMOTE_COMEBACKHOME_HOUSEHOLD_0013_0015`, `expected_sha`는 1번의 40자리 SHA로 지정합니다. 브랜치가 그사이 바뀌었으면 실행은 중단됩니다.
4. 워크플로가 기존 DB의 적용 이력과 구조를 확인하고, 복구할 수 있는 시점을 조회·기록한 뒤 승인된 `0013`–`0015`만 추가합니다. 작업 완료 요약에 `schema: applied` 또는 `already-applied`가 있어야 다음으로 진행합니다.
5. 그다음 승인된 PR을 main에 병합하고 기존 Pages와 기존 스케줄러 Worker 배포를 확인합니다. 새 주소나 서비스를 만들지 않습니다.
6. 운영에서 로그인·일정·산재 자료함을 확인하고, 생활비 첫 화면에서 가계부를 준비합니다. Sheets API가 꺼져 있다면 [Google 설정 안내](../../public/guides/household-drive-setup.html)를 따릅니다. 실제 알림은 각 기기에서 사용자가 켠 뒤 확인합니다.

**DB 준비가 병합보다 먼저입니다.** 기존 Pages의 Git 연동은 main 변경을 자동 배포할 수 있습니다. DB를 준비하지 않고 먼저 병합하면 새 생활비·ChatGPT 답변 화면이 열리지 않을 수 있습니다. 일반 상태 확인 API가 성공해도 새 테이블이 준비됐다는 뜻은 아닙니다.

GitHub가 main의 이전 입력 화면만 보여 준다면 담당 실행자가 같은 기존 워크플로를 검수 브랜치와 명시된 입력값으로 실행합니다. 새 입력칸을 보이게 하려고 기능 코드를 먼저 main에 병합하지 않습니다.

## 보존하는 내용

- 기존 일정, 사람, 로그인 계정, 산재 기록과 원본 자료를 변경하지 않습니다.
- `0013`: 생활비 동기화 상태와 카드 이미지 업로드 영수증을 저장할 빈 테이블만 만듭니다.
- `0014`: ChatGPT 전달 문서와 답변을 연결할 빈 테이블·색인을 만듭니다.
- `0015`: 기기별 알림 설정과 발송 대기 상태를 저장할 빈 테이블·색인을 만듭니다.
- 금융 기록·파일 업로드·실제 푸시 발송은 이 워크플로에서 수행하지 않습니다.

## 실행 장치

`scripts/private-work/prepare-household-db.mjs`는 기존 DB ID와 전체 15개 SQL 파일의 검수 해시를 확인합니다. 운영 이력은 정확히 `0001`–`0012` 또는 이미 완료된 `0001`–`0015`만 허용합니다. SQL 정의가 다른 경우에도 쓰기 전에 중단합니다.

실제 Wrangler 적용에는 승인된 **세 파일만 복사한 임시 폴더**를 사용합니다. 저장소에 다른 SQL이 늘어나더라도 한꺼번에 적용하지 않습니다. 기존 `0012` 로그인 준비 도구는 이전의 엄격한 검사 규칙을 유지하며, 이번 묶음을 적용하는 용도로 사용하지 않습니다.

## 오류가 나오면

사용자는 워크플로 주소와 마지막 오류 이름만 전달하면 됩니다. 비밀번호·토큰·DB 내용을 게시하지 마세요.

- `REVIEWED_COMMIT_REQUIRED`: 승인한 SHA와 선택한 브랜치의 실제 커밋이 다릅니다. 최신 CI를 확인한 뒤 정확한 SHA로 다시 준비합니다.
- `BASELINE_OR_PARTIAL_SCHEMA_MISMATCH`: 운영 구조가 예상과 다릅니다. 담당 실행자가 읽기 전용으로 차이를 확인합니다.
- `RECOVERY_POINT_UNAVAILABLE`: 복구 시점 조회가 되지 않았습니다. DB 쓰기는 실행되지 않습니다.
- `PARTIAL_HOUSEHOLD_BATCH_STOP` 또는 `MIGRATION_APPLY_FAILED_INSPECT_PARTIAL_BATCH`: 일부 파일까지만 적용됐을 수 있습니다. **같은 작업을 무작정 재실행하지 않습니다.** 담당 실행자가 적용 이력·추가된 구조를 확인하고 남은 파일만 대상으로 다시 검수합니다.

D1은 개별 migration 실패를 되돌려도 그전에 성공한 파일은 유지합니다. 세 파일 전체가 하나의 거래처럼 되돌아간다고 가정하지 않습니다. Time Travel 복원은 운영 DB 전체를 과거로 돌리므로 이후 입력한 일정도 사라질 수 있습니다. 이 도구는 자동 복원이나 테이블 삭제를 실행하지 않습니다.

소프트웨어 검증: `node --test test/private-work/login-db-setup.test.mjs test/private-work/household-db-setup.test.mjs`. 로컬 검증 성공은 운영 적용·실제 Google Sheets 계산·iPhone 푸시 성공과 별개입니다.
