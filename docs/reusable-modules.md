# 재사용 모듈과 제품 정책의 경계

2026-10-21 사용자가 기존 운영 기능과 PR #98 iPhone UI를 정상 확인한 뒤 요청한 동작 보존 정리입니다. 기준 MAIN은 `04a7d47e4a444dba85840b22adad56454064eb25`입니다.

## 소유권

| 계층 | 소유한 내용 | 의존 가능한 방향 |
| --- | --- | --- |
| `packages/portable` | 재사용 가능한 실행부·프리미티브 | 같은 패키지, 명시한 peer만 |
| `src/domain`, `src/application` | 근무·일정·ETA·선호 경로·승인·알림 정책 | 제품 계약, 순수 공통 함수 |
| `src/providers`, `src/pwa`, `src/app` | 공급자 연결, 제품 설정·저장 키·캐시 허용 목록, 조립 | 제품 계약과 공통 실행부 |
| `src/shared`, `src/features`, `src/pages` | 한국어 문구, 제품 레이아웃·스타일·사용 흐름 | 아래 계층의 공개 계약 |
| `worker` | 제품 API·D1 저장소·Outbox·스케줄러·비밀키 주입 | 제품 계약, 공통 HTTP/D1/Push 실행부 |

공통 실행부를 앱이 가져다 쓰며 공통 모듈은 앱을 역으로 가져오지 않습니다. 모듈마다 진입점을 분리해서 서버 Push 코드가 UI 진입점을 통해 포함되지 않도록 했습니다. 범용 DI 컨테이너·별도 서비스·새 데이터베이스는 도입하지 않았습니다.

## 유지되는 호환성

기존 파일 경로는 얇은 재수출 또는 제품 설정을 넣는 어댑터로 남깁니다. 기존 호출부와 런타임 회귀 검사는 계속 그 경로를 사용합니다. 캐시 60초, 기존 저장 키, 요청 공유, 변경 후 무효화, 원자적 승인, VAPID/재시도, 실제 출발 미확인 처리, 서울 날짜 기준은 바꾸지 않습니다.

UI 레이아웃과 클래스는 유지합니다. 시간 휠 CSS만 공통 변수로 분리하고 앱 변수 연결을 두었습니다. 닫기·드래그·포커스·로딩 지연·테마 엔진을 옮겼으며, 테마는 기존처럼 CSS/React 전에 동기 실행됩니다. 타이틀을 내리거나 상태 영역·하단바 CSS를 재수정하지 않습니다.

OCR의 픽셀 표 분석·래스터·CTC·Tesseract 실행부는 공통화합니다. 7×3 해석, 사람/날짜 매칭, OFF/BLANK/UNREADABLE, 검토·명시 승인·저장, 모델 무결성과 제품 품질 기준은 앱에 남깁니다. 범용 OCR FAIL2는 기존 비차단 정책 그대로이며 모듈화로 정확도가 개선되었다고 주장하지 않습니다.

## 검증 방식

`npm run verify:portable`은 다음을 검사합니다.

1. 패키지의 import가 `src`/`worker`나 미선언 라이브러리로 나가지 않는지 검사합니다.
2. 기존 어댑터가 실제 새 구현 파일을 참조하는지 검사합니다.
3. 새 임시 폴더에 모듈을 내보내고, 원본 앱 없이 타입 검사를 실행합니다. 기존 설치 의존성만 연결하며 네트워크 호출을 하지 않습니다.
4. 복사본에서 캐시 중복 공유·TTL·무효화 경합·인스턴스 분리, HTTP 오류·성공 변경, 페이지 복귀, 재시도, 날짜 경계, 생일, D1 실패, CTC 확률, 실제 테마 부트스트랩을 실행합니다.

기존 텍스트 기반 계약 검사는 `scripts/lib/implementation-source.mjs`가 어댑터와 `test/portable-adapters.json`의 구현 파일을 함께 읽도록 바꿉니다. 검사 조건을 삭제하지 않으며, 실제 참조 관계를 별도 확인하므로 무관한 파일의 문자열로 PASS를 만들 수 없습니다. 실행 기반 테스트는 기존 앱 API를 사용합니다.

필수 Actions 12개 작업, Chromium/WebKit, 격리 D1, XLSX/Paddle/Push 암호화 회귀를 유지합니다. 공통 모듈만 바뀌어도 이 워크플로가 실행되도록 경로 필터를 추가합니다. 운영 확인은 정확한 배포 커밋을 대상으로 읽기만 수행합니다.

## 향후 확장

새 프로젝트에서는 필요한 모듈만 복사하고 자기 저장 키·문구·디자인·승인 규칙을 넣습니다. 새 공통화 후보는 실제 두 사용처가 같은 계약을 공유할 때 추가합니다. ComeBackHome의 화면, 스케줄러, DB 스키마를 범용 패키지에 넣지 않습니다. 모듈의 수정은 공통 계약 검사와 영향을 받는 제품 회귀를 통과해야 합니다.

## 배포 검증 정리

PR #99 병합 때 기존 자동 스케줄러 배포 워크플로의 확인 단계가 운영 scheduler-tick을 한 번 호출한 사실을 기록했습니다. 이 결과만으로 실제 발송 건수를 판단하지 않습니다. 스케줄러 코드·Cron·설정은 바꾸지 않았습니다. 후속 정리에서는 이 배포 확인 요청을 GET /api/health로 바꾸고, 운영 예약 처리 POST가 다시 들어가지 못하도록 계약 검사를 추가했습니다. 실제 스케줄러 인증·전달·D1 동작 검증은 기존 격리 테스트가 담당합니다. 정상 운영 Cron 자체는 계속 유지합니다.
