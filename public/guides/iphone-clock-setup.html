iPhone 시계 알람 단축어 만들기

ComeBackHome에서 출근 90분 전·퇴근 30분 후의 시각을 보내고, 단축어가 확인한 항목만 시계 앱에 적용합니다. 휴무에는 새 알람을 만들지 않습니다.

현재는 구성·검토용 안내입니다. 실제 설치·실행·알람 변경은 별도 기기 시험 승인 후 진행하세요. 이 안내를 열어도 시계 알람은 바뀌지 않습니다. 아래 단축어는 iPhone 실기기에서 아직 검증하지 않았습니다.

Apple이 서명한 설치 파일이나 iCloud 설치 링크는 없습니다. 아래 순서로 직접 구성하는 방법을 제공합니다. 일반 텍스트를 .shortcut으로 바꾸어 설치 파일이라고 제공하지 않습니다.

준비 · 입력 확인 · 변경 목록 · 적용 · 기기 시험

1. 처음 한 번 준비

  1. iPhone의 설정 → 일반 → 날짜 및 시간에서 시간대가 서울인지 확인합니다. 해외 시간대로 바꾸면 이 단축어를 실행하지 않습니다.
  2. 파일 → 둘러보기 → 나의 iPhone에 ComeBackHome 폴더를 만듭니다. iCloud Drive에 만들거나 다른 기기와 기록 파일을 공유하지 않습니다.
  3. ComeBackHome에서 대상 사람을 선택하고 설정 → iPhone 시계 알람 → 단축어 설정 방법에 보이는 연동 식별자 전체를 복사합니다. 예시를 복사하지 마세요. 브라우저 저장소를 지우거나 사람을 바꾸면 이 값이 달라집니다.
  4. 단축어 → +를 누르고 이름을 정확히 ComeBackHome 알람 동기화로 바꿉니다. 액션 검색에 아래 한국어 이름이 없으면 괄호 안 영문 이름으로 검색합니다. iOS 버전에 따라 번역·표시는 다를 수 있습니다.
  5. 아래에 나오는 알람 찾기(Find Alarm), 알람 생성(Create Alarm), 알람 삭제(Delete Alarms), 알람 토글(Toggle Alarm) 액션을 검색해 존재하는지 확인합니다. 알람 변수에서 레이블(Label), 시간(Time), 활성화(Is Enabled), 반복(Repeat)을 선택할 수 있는지도 확인합니다. 필요한 액션·속성이 없으면 여기서 멈추고 iOS 버전과 해당 화면만 알려주세요. 다른 개인 알람을 대신 선택하지 않습니다.

첫 기록 파일 만들기 — 최초 설정일 때만

별도의 임시 단축어에 텍스트(Text)를 넣고 아래 JSON의 여기에_복사한_연동_식별자만 바꿉니다. 다음에 이름 설정(Set Name)을 clock-ledger.json으로, 파일 저장(Save File)의 폴더를 나의 iPhone/ComeBackHome으로 지정합니다. ‘저장 위치 묻기’는 끄고, 최초 실행에서는 ‘파일이 있으면 덮어쓰기’를 끕니다. 이 초기화 단축어에는 시계 액션을 넣지 않습니다.

{"schema":"cbh-clock-ledger/v1","scope":"여기에_복사한_연동_식별자","receipts":[],"pending":null}

이미 이 파일이 있으면 새 파일로 덮어쓰지 않습니다. 기록이 없어진 경우에도 자동 초기화하지 않습니다. 이전 앱 알람이 남았는지 확인하는 복구 절차가 먼저 필요합니다.

액션 연결 방법

표의 변수 설정(Set Variable)은 직전 결과를 지정한 이름으로 보관합니다. 다른 입력을 지정할 때는 입력 칸을 길게 눌러 ‘변수 선택’에서 해당 이름을 선택합니다. 각 항목 반복(Repeat with Each) 안에서는 현재 항목을 ‘반복 항목’으로 받습니다. 중첩 반복 전에는 바깥 항목을 별도 변수에 저장합니다.

아래의 중단은 반드시 두 액션을 뜻합니다: 알림 보기(Show Alert)로 이유를 표시하고, 바로 다음에 이 단축어 중단(Stop This Shortcut / Stop and Output)을 놓습니다. 알림만 표시하고 계속 진행하면 안 됩니다.

2. 입력과 기록 확인

이 단계에는 알람 생성·삭제·토글을 넣지 않습니다. 모든 조건을 통과한 뒤에만 변경 목록을 만듭니다.

순서추가할 액션과 입력
1텍스트: 복사한 연동 식별자 전체 → 변수 설정 고정범위. 이 값은 받은 JSON에서 가져오지 않습니다.
2조건문(If): 단축어 입력이 값이 없으면 ‘ComeBackHome에서 다시 계산 후 실행해 주세요’ → 중단. 입력에서 사전 가져오기(Get Dictionary from Input): 단축어 입력 → 변수 계획. JSON 오류는 그대로 중단합니다.
3사전 값 가져오기(Get Dictionary Value)로 계획의 각 키를 읽고, 각각 조건문: 다음과 다름을 추가합니다: schema = cbh-clock/v1, scope = 고정범위, timezone = Asia/Seoul, requiresDailySync = 참, deviceApplied = 거짓. 하나라도 다르면 중단합니다.
4현재 날짜(Current Date) → 현재. 날짜 포맷(Format Date): 현재, 사용자화 Z → 값이 +0900과 다르면 중단합니다. 설정의 서울 시간대 확인과 함께 사용합니다.
5사전 값 가져오기 generatedAt → 입력에서 날짜 가져오기(Get Dates from Input) → 개수(Count)가 1이 아니면 중단 → 첫 항목을 생성에 저장. expiresAt도 같은 순서로 만료에 저장.
6날짜 사이의 시간 가져오기(Get Time Between Dates): 생성→만료, 단위 초. 0 이하 또는 300 초 초과면 중단. 생성이 현재보다 뒤이거나, 만료가 현재 이하이면 중단. 날짜 조정(Adjust Date): 생성에 24시간 더하기 → 마감.
7폴더에서 파일 가져오기(Get File from Folder): 폴더 나의 iPhone/ComeBackHome, 경로 clock-ledger.json, ‘파일이 없으면 오류’ 켜기 → 입력에서 사전 가져오기 → 기록. 파일·JSON 오류는 중단하고 빈 기록으로 대체하지 않습니다.
8기록의 schema가 cbh-clock-ledger/v1인지, scope가 고정범위와 같은지 각각 확인. pending에 값이 있으면 ‘이전 동기화가 중단되었습니다. 기록과 앱 알람 확인이 필요합니다’ → 중단.
9계획의 targets → 대상목록, 기록의 receipts → 기록목록. 유형 가져오기(Get Type)로 목록인지 확인하고 각각 개수가 48을 넘으면 중단. 빈 목록은 정상입니다. 목록(List)의 기본 항목을 모두 제거 → 변수 본레이블.

대상목록 검사 반복

각 항목 반복의 입력을 대상목록으로 지정하고, 아래 액션을 반복 안에 순서대로 넣습니다. 반복 항목을 대상으로 저장합니다. 사전 값 가져오기의 입력은 항상 대상입니다.

  1. id / label / fireAt / clockTime / workDate / kind를 각각 같은 이름의 변수로 저장합니다. 하나라도 없으면 중단합니다. 텍스트 일치(Match Text)로 clockTime이 ^(?:[01]\d|2[0-3]):[0-5]\d$, workDate가 ^20\d{2}-\d{2}-\d{2}$에 일치하는지 확인합니다. 일치 결과가 없으면 중단합니다.
  2. kind가 START_MINUS_90도 END_PLUS_30도 아니면 중단합니다. 고정범위를 텍스트 분할(Split Text)에서 :로 분할하고 목록에서 항목 가져오기(Get Item from List)의 세 번째 항목을 사람코드로 저장합니다.
  3. 텍스트에 변수 칩을 넣어 [사람코드]:[workDate]:[kind]를 만듭니다. 결과가 id와 다르면 중단. 다른 텍스트에 [고정범위][id]를 넣고 label과 다르면 중단합니다. ‘포함’이 아닌 전체 일치를 사용합니다.
  4. 조건문: 본레이블 목록이 label을 포함하면 중단. 아니면 변수에 추가(Add to Variable)로 label을 본레이블에 추가합니다.
  5. fireAt에서 날짜를 가져오고 개수가 1인지 확인 → 울릴날짜. 현재보다 뒤이며 마감보다 앞인지 확인. 날짜 포맷 사용자화 HH:mm 값이 clockTime과 같은지, ss 값이 00인지 확인합니다.
  6. kind가 START_MINUS_90이면 울릴날짜에 90분을 더하고 yyyy-MM-dd로 포맷한 값이 workDate와 같아야 합니다. END_PLUS_30이면 울릴날짜에서 30분을 빼고 포맷한 값이 workDate 또는 workDate 다음 날짜여야 합니다. workDate는 날짜(Date)의 지정 날짜에 [workDate]T00:00:00+09:00를 넣어 변환한 뒤 동일 포맷으로 되돌려 원래 값과 비교합니다. 일치하지 않으면 잘못된 날짜이므로 중단합니다.

이제 ‘반복 종료’ 뒤로 나옵니다. 출퇴근의 ±90/30 계산은 앱이 이미 했습니다. 단축어에서 다시 더하거나 빼지 않습니다.

3. 개인 알람을 제외한 변경 목록 만들기

목록의 항목을 모두 지운 빈 목록을 네 번 만들어 각각 유지기록, 삭제알람, 켜기알람, 생성대상에 저장합니다. 삭제알람·켜기알람에는 텍스트가 아니라 알람 찾기에서 반환된 알람 객체만 넣습니다.

기록목록을 각 항목 반복

  1. 반복 항목 → 기존기록. 사전 값으로 targetId / label / clockTime / fireAt를 읽습니다. label = 고정범위 + targetId 전체 일치, clockTime 형식, fireAt 날짜 변환을 위와 같이 확인합니다. 기록목록의 같은 label이 두 번 나오면 중단합니다. 이 반복 바로 앞에서 빈 목록을 만들어 변수 본기록레이블에 저장합니다. 각 반복에서 본기록레이블에 label이 포함되면 중단하고, 아니면 label을 변수에 추가합니다.
  2. 알람 찾기(Find Alarm): 필터 레이블이 label과 같음, 제한 끄기 → 변수 일치알람. 개수가 2 이상이면 중단. 0이면 이 항목은 삭제·토글 대상에 넣지 않고 다음 기록으로 넘어갑니다.
  3. 개수가 1인 조건문 안에서 목록에서 첫 항목 가져오기 → 실제알람. 실제알람의 시간 속성을 날짜 포맷 HH:mm으로 변환합니다. 기록의 clockTime과 다르거나 반복이 ‘안 함’이 아니면 ‘시계에서 직접 바뀐 앱 알람입니다’ → 중단합니다.
  4. 숫자(Number) 0 → 유지수. 각 항목 반복 대상목록 안에서, 대상의 label·clockTime·fireAt가 기존기록의 세 값과 모두 같으면 유지수에 1을 더합니다(계산 Calculate → 변수 설정).
  5. 유지수가 1이면 기존기록을 유지기록에 추가합니다. 실제알람의 활성화가 거짓이면 실제알람을 켜기알람에 추가합니다. 유지수가 0이면 실제알람을 삭제알람에 추가합니다. 2 이상이면 중단합니다. 조건문과 안쪽 반복을 닫은 뒤 다음 기존기록으로 진행합니다.

대상목록을 다시 각 항목 반복

  1. 반복 항목을 새대상으로 저장합니다. 유지기록에 새대상의 label과 같은 항목이 있으면 추가 작업이 없습니다. 없는 경우에만 아래를 수행합니다. 비교는 ‘각 항목 반복 + 조건문 + 개수 변수’로 위와 동일하게 구성합니다.
  2. 알람 찾기: 레이블이 새대상.label과 같음, 제한 끄기. 결과가 있는데 기록목록에는 그 label이 없으면 중단합니다. 이것은 소유권을 확인할 수 없는 알람입니다. 레이블 앞부분이 CBH라고 자동 채택하거나 삭제하지 않습니다.
  3. 기록에는 있으나 일정이 바뀌어 삭제알람에 들어간 항목, 또는 시계에 결과가 0개인 항목만 생성대상에 추가합니다. 같은 label의 알람이 2개 이상이면 중단합니다.

4. 목록 확인 후 한 항목씩 적용

텍스트에 삭제알람·켜기알람·생성대상의 각 레이블과 시각, 개수를 넣습니다. 목록에서 선택으로 일부 항목을 골라 적용하는 기능은 넣지 않습니다. 전체 계획에 대해 메뉴에서 선택(Choose from Menu): ‘취소’와 ‘이 앱 알람만 적용’을 만듭니다. 취소 가지에는 중단, 적용 가지에만 아래 액션을 넣습니다. 실제 iPhone 시험 승인 전에는 이 적용 가지를 실행하지 않습니다.

‘현재 날짜’를 다시 읽고 만료보다 앞인지 확인합니다. 만료 시각과 같거나 지났으면 앱으로 돌아가 다시 계산합니다. 첫 시계 변경 전에 기록 파일을 다시 읽어 이전에 읽은 내용과 같은지 확인합니다. 다른 실행이 기록을 바꿨으면 중단합니다. 동시에 두 번 실행하지 않습니다.

각 시계 액션 직전에도 시간 검사를 반복합니다. ‘현재 날짜’를 새로 읽고 만료보다 앞인지 확인합니다. 생성·켜기 대상은 fireAt가 현재보다 뒤여야 합니다. 시각이 지났으면 중단하고 앱에서 다시 계산합니다. 이미 지난 시각으로 시계 알람을 만들면 다음 날 울릴 수 있습니다. Apple 확인 창에서 오래 기다린 경우에는 취소하고 다시 계산하세요. 이미 저장한 pending은 자동으로 지우지 않습니다.

기록 파일을 저장하는 공통 액션 묶음

아래 각 단계에서 ‘기록 저장’이 나오면 이 액션들을 해당 위치에 넣습니다. 사전 값 설정(Set Dictionary Value)으로 기록의 receipts와 pending을 지정 → 변수 설정 기록 → 입력에서 텍스트 가져오기(Get Text from Input)의 입력 기록 → 이름 설정 clock-ledger.json → 파일 저장, 폴더 나의 iPhone/ComeBackHome, 저장 위치 묻기 끄기, 덮어쓰기 켜기. 바로 폴더에서 파일 가져오기 → 입력에서 사전 가져오기로 다시 읽고 저장한 scope·pending.operation·pending.label과 receipts 전체의 targetId·label·clockTime·fireAt가 같은지 항목별로 확인합니다. 오류가 나면 즉시 중단합니다.

pending을 비울 때는 텍스트의 {"schema":"cbh-clock-ledger/v1","scope":"[고정범위]","receipts":기록목록JSON,"pending":null}을 사전으로 변환해 기록에 저장합니다. 대괄호 표시는 문자로 쓰지 않고 변수 칩을 넣는 자리입니다. 기록목록JSON은 각 기록을 ‘입력에서 텍스트 가져오기’로 JSON으로 만든 뒤 ‘텍스트 결합(Combine Text)’ 사용자화 구분자 ,로 연결하고 바깥에 [와 ]를 붙인 텍스트입니다. 빈 목록이면 []입니다. 저장 전 사전 변환이 실패하면 중단합니다.

  1. 각 항목 반복: 삭제알람. 항목의 label로 알람을 다시 찾고 개수가 정확히 1인지, 시간·반복이 기록과 같은지 다시 확인합니다. 기록의 pending을 사전 operation=DELETE, label=이번 레이블로 설정하고 기록 저장. 성공한 뒤에만 알람 삭제(Delete Alarms) 입력을 방금 찾은 한 알람 객체로 지정합니다. Apple 확인은 켜 둡니다. 빈 입력으로 실행하지 않습니다.
  2. 동일 label을 다시 찾습니다. 0개여야 삭제 성공입니다. 해당 항목을 제외한 새 기록목록을 ‘각 항목 반복 + 조건문 + 변수에 추가’로 만듭니다. receipts를 새 목록으로, pending을 null로 저장합니다. 중단·오류가 발생하면 pending을 지우지 않습니다.
  3. 각 항목 반복: 켜기알람. label·시각이 여전히 일치하고 반복이 ‘안 함’인 단일 객체를 다시 찾습니다. 해당 label의 대상.fireAt와 현재 날짜를 비교해 아직 미래인지 다시 확인합니다. 알람 토글의 동작을 켜기(Turn On)로 고정하고 그 객체만 입력합니다. ‘전환/Toggle’로 두면 재실행 시 꺼지므로 금지합니다. 다시 찾아 활성화가 참인지 확인합니다.
  4. 각 항목 반복: 생성대상. label로 알람을 다시 찾고 0개인지 확인합니다. pending을 operation=CREATE, label=대상의 label인 사전으로 저장합니다. 성공한 뒤 알람 생성(Create Alarm): 시간은 대상.fireAt에서 가져온 날짜, 레이블은 대상.label 전체, 반복은 안 함. 시간 입력이 시각만 허용되는 버전에서는 대상.clockTime을 지정합니다.
  5. label로 다시 찾고 정확히 1개인지 확인합니다. 시간 HH:mm이 대상.clockTime, 활성화가 참, 반복이 안 함이어야 합니다. 먼저 빈 목록 → 변수 교체기록을 만들고, 각 항목 반복: 기록목록에서 label이 대상.label과 다른 기록만 교체기록에 추가합니다. 사전에 targetId=대상.id, label=대상.label, clockTime=대상.clockTime, fireAt=대상.fireAt을 넣어 교체기록에 한 번 추가 → 변수 설정 기록목록. 시계에서 앱 알람을 직접 삭제했다가 재생성해도 같은 label의 기록이 두 개 생기지 않도록 하는 순서입니다. receipts를 이 새 목록으로, pending을 null로 기록 저장합니다. 확인 실패 시 성공 기록을 쓰지 않습니다.
  6. 모든 반복이 끝나면 알림 보기: ‘앱 알람 동기화가 끝났습니다. 시계 앱의 시각을 확인해 주세요’. 이 메시지는 실제 울림 시험이 끝났다는 뜻이 아닙니다. 앱에는 적용 성공을 되돌려 보내거나 자동으로 표시하지 않습니다.

5. 일상 사용과 중단 복구

처음에는 iPhone 단축어 앱에서 구성만 검토하세요. 기기 시험을 승인한 뒤 앱의 ‘개인 알람 보호 절차를 포함한 단축어를 설정했습니다’를 체크하고 단축어에서 확인하고 적용을 누릅니다. 매일 또는 일정 변경·휴무 변경 후 같은 절차로 동기화합니다. 24시간보다 먼 알람은 보내지 않습니다. PWA가 닫힌 동안 날짜가 바뀌었다고 자동으로 알람을 새로 만들지는 않습니다.

pending 경고가 있으면 실행을 반복하거나 파일을 초기화하지 않습니다. clock-ledger.json의 pending.label 하나를 시계 앱에서 확인합니다. CREATE는 실제 생성 여부를 확인해 성공 기록을 복구하거나 그 앱 알람 하나만 직접 정리하고, DELETE는 해당 앱 알람이 삭제됐는지 확인한 뒤 기록에서 해당 항목을 정리합니다. 다른 개인 알람은 건드리지 않습니다. 불확실하면 중단 상태를 유지합니다.

특정 알람음 선택을 이 구성으로 보장하지 않습니다. 시계 앱에서 각 앱 알람의 사운드를 직접 확인해야 합니다. 일정 변경으로 알람을 다시 만들면 소리를 다시 확인해야 합니다. 무음·집중 모드·음량·배터리 상태와 실제 울림은 실기기 시험 항목입니다.
